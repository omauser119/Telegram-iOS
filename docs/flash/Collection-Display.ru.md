# Flash: Collection Display Settings

Доступно только аккаунтам с `network.isFlashEnvironment == true`.
Настройки привязаны к аккаунту и владельцу коллекции (`InputPeer`).
Контракт: [collection-display.tl](collection-display.tl). Все шесть ID фиксированы.

## Интерфейс

В меню коллекции добавлены Set as Main Tab / Remove as Main Tab и Hide / Show Collection.
Владелец видит скрытые вкладки с пометкой Hidden и может вернуть их.
Другим пользователям скрытые вкладки не показываются.
Главная видимая коллекция стоит перед All Gifts и выбирается при открытии профиля.
Явно открытая коллекция по ссылке имеет приоритет над главной вкладкой.
Reorder предварительно загружает весь состав, включая отфильтрованные подарки.
Угол плитки можно нажать или потянуть для переключения compact / expanded.
Перетаскивание подарка после удержания меняет порядок; Done сохраняет полный список.
Первая расширенная плитка занимает 2×2 ячейки, остальные расширенные — 2×1.
Раскладка анимируется пружиной; число колонок адаптируется к экрану.
При ошибке сохранения правки остаются в режиме редактирования для повторной попытки.

## Протокол

Опциональные hidden/main_tab передаются как полноценные boxed Bool, включая false.
В ответах эти значения определяются только битами 0/1, без Bool в потоке.
Неуказанные параметры обновления не сериализуются и сохраняют серверное значение.
Hash хранится в контексте аккаунта/peer как непрозрачный Int64, первый запрос использует 0.
NotModified сохраняет предыдущие настройки; после update выполняется повторный get.
После изменения items очищаются стандартные кеши списка коллекций и состава коллекции.
Все страницы состава запрашиваются с collection_id (flags = 1 << 6), без фильтров.
Проверяются циклы next_offset, дубликаты, неизменность count и полнота последней страницы.
Перед отправкой items состав снова сверяется с сервером; изменения состава требуют перезагрузки.
Для пользовательского peer используется msg_id, для канала — saved_id.
StarGift.id и uniqueGift.id для сопоставления не используются.
Проверяются уникальность gift_id, перестановка order 0...N−1 и size 0/1.
Маски: unlimited=1, limited=2, upgradable=4, unique=8, displayed=16, hidden=32.
Следовательно displayed + hidden = 48; число 24 означает unique + displayed.
Биты Limited/Upgradable преобразуются отдельно: стандартный iOS-фильтр использует обратный порядок.
Запросы и элементы интерфейса Flash не включаются для Production/Test.
На чужом профиле сохранение настроек недоступно; право записи также проверяет сервер.

## Проверка

`python3 tools/flash/test-contract.py` запускает Swift 6.2 в Docker.
Проверяются все 16 комбинаций флагов, false, пустой vector и непрозрачный hash.
Проверяются фиксированные ID, усечение ответов, лишние байты и неверные vector-конструкторы.
Проверяются некорректные items, преобразование всех 64 масок и отсутствие пересечений плиток.
Тест использует реальные Flash-сериализаторы, reader и алгоритм раскладки.
Стандартный InputPeerSelf заменён минимальной заглушкой; Foundation адаптируется только во временной копии.
Парсер Swift проверен для изменённых файлов; полная iOS-сборка требует Xcode.
Визуальная проверка на iPhone и проверка round-trip с Flash-сервером пока не выполнены.
